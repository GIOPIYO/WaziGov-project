# WaziGov NLP Module Documentation

## Overview

The `NLP-module` branch encompasses the Natural Language Processing (NLP) components of the WaziGov project. The primary goal of this module is to extract structured financial data (such as budgeted amounts, expenditures, and county names) from unstructured text documents, specifically Markdown files generated from official government reports (like the Controller of Budget - COB, and the Office of the Auditor General - OAG).

The core of this extraction process relies on a custom-trained, locally hosted Named Entity Recognition (NER) model: `wazigov-bert-v1`.

---

## 1. Core Components

### 1.1 Model: `wazigov-bert-v1`
- **Type**: BERT-based Token Classification model for Named Entity Recognition (NER).
- **Execution**: Runs entirely locally via the HuggingFace `pipeline`. It requires no internet connection for inference.
- **Labels extracted**:
  - `B-COUNTY` / `I-COUNTY`: County names.
  - `B-AMOUNT` / `I-AMOUNT`: Financial figures.
- **Features**: Configured with `aggregation_strategy="simple"` to automatically merge Begin (`B-`) and Inside (`I-`) tags into cohesive entities, handling WordPiece artifacts seamlessly.

### 1.2 `batch_processor.py`
This script is designed for bulk data extraction.
- **Functionality**: It scans a specified directory (`NLP module/wazigov-engine/data/processed/`) for `.md` files. It reads these files line-by-line (or paragraph-by-paragraph) and feeds the text into the `wazigov-bert-v1` model.
- **Output**: The extracted entities (Counties and Amounts), along with the source filename and confidence scores, are saved into a single CSV file: `wazigov_extracted_budgets.csv`.
- **Data Cleaning**: The script automatically removes spaces from extracted amount strings to ensure clean numerical data.

### 1.3 `test_inference.py`
This is a lightweight script used to verify that the local model is working correctly.
- **Functionality**: It loads the `wazigov-bert-v1` model and runs a hardcoded test sentence through the NER pipeline.
- **Usage**: Useful for quick debugging or verifying the environment setup before running the heavier `batch_processor.py`.

### 1.4 The `wazigov-engine` Sub-module
This directory contains the backend infrastructure that utilizes the NLP extractions:
- **`api/`**: Contains a FastAPI application that serves the extracted data.
  - `models.py` & `schemas.py`: Define the database structure (e.g., `FinanceSummary`, `Project`, `AuditRun`).
  - `database.py`: Handles PostgreSQL connections, configurable via environment variables (`DATABASE_URL`).
- **`triangulator.py` (and `test_triangulator.py`)**: A critical script (and its unit tests) that cross-references extracted data from COB reports with findings from OAG reports. It uses NLP models to link projects, detect risk flags (like "stalled" or "incomplete" projects), and generate "triangulation verdicts" to flag discrepancies or corroborations.

## 2. Environment Setup & Execution

### 2.1 Prerequisites
- Python 3.8+
- Required libraries (install via `pip`):
  ```bash
  pip install transformers torch psycopg2-binary sqlalchemy fastapi uvicorn
  ```
  *(Note: See `requirements.txt` if available in the root for exact versions).*

### 2.2 Running the Standalone Test
To quickly verify the NER model:
1. Navigate to the NLP module directory:
   ```bash
   cd "NLP module"
   ```
2. Run the test script:
   ```bash
   python test_inference.py
   ```
   *Expected Output: A table showing the extracted entities (Counties and Amounts) from the sample text with their confidence scores.*

### 2.3 Running the Batch Processor
To process a folder of markdown documents:
1. Ensure your `.md` files are located in: `NLP module/wazigov-engine/data/processed/`
2. Run the script:
   ```bash
   cd "NLP module"
   python batch_processor.py
   ```
3. Check the output: The results will be saved in `NLP module/wazigov_extracted_budgets.csv`.

## 3. Recent Updates & Focus Areas

The `NLP-module` branch has seen several recent integrations:
1.  **Database Configuration Updates**: `wazigov-engine/api/database.py` was updated to prefer the `DATABASE_URL` environment variable for flexible local and cloud PostgreSQL connections.
2.  **Triangulator Refinement**: The addition of `test_triangulator.py` ensures robust testing for the logic that links COB and OAG reports. This highlights the project's focus on not just extracting data, but *corroborating* it across different government sources to find actionable insights (e.g., flagging stalled projects).
3.  **Data Models**: Updates in `models.py` and `schemas.py` show ongoing work to map NLP extractions into structured SQL tables (`FinanceSummary`).

## 4. Integration into WaziGov
The outputs from this NLP module (specifically the CSVs and database entries generated by the engine) act as the primary data source for the WaziGov user interface (`wazi-ui` and `wazigov-ui-module`). By turning unstructured PDFs/Markdown into structured tables, this module is the backbone of WaziGov's transparency and accountability dashboards.
